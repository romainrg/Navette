# Spike findings for 0.1

Run on 2026-11-10, macOS 27.0.1, OpenSSH 10.3p1, Xcode 16.2. The throwaway sources are on the local branches `spike/sftp` and `spike/ftps`, which are never merged.

## S1. System SSH, askpass, SFTP v3 — passed

Server: `/usr/sbin/sshd` as the current user on port 22222, temporary host key and `authorized_keys`, passphrase-protected client key.

| Question | Result |
|---|---|
| `ssh -s -- host sftp` over pipes | INIT/VERSION, `OPENDIR`, `READDIR`, `CLOSE` all work. Names come back as raw bytes (NFC, emoji, spaces checked). |
| Extensions advertised | `posix-rename`, `statvfs`, `fstatvfs`, `hardlink`, `fsync`, `lsetstat`, `limits`, `expand-path`, `copy-data`, `home-directory`, `users-groups-by-id` |
| Limits | packet 262144, read 261120, write 261120 |
| Askpass from a hardened-runtime, ad hoc signed binary | Works. The helper talks to the app over a Unix socket. |
| What the helper receives | The prompt as `argv[1]`. `SSH_ASKPASS_PROMPT` is **not set** for the host key question or the passphrase. The host key question expects the text `yes` (or `no`) on stdout. A non-zero exit cancels. |
| Wrong passphrase | The same prompt is asked three times, then `Permission denied (publickey)`, exit 255. |
| Long key paths | `ssh` truncates the path in the passphrase prompt; the classifier must not rely on the full path. |
| Changed host key | Askpass is not called. Exit 255, stderr contains `REMOTE HOST IDENTIFICATION HAS CHANGED`, the SHA256 fingerprint and `Offending <type> key in <file>:<line>`. |
| Unreachable / unknown host | Exit 255 with `Connection refused` or `Could not resolve hostname`. |
| Host that looks like an option, after `--` | Rejected by `ssh`: `hostname contains invalid characters`. |
| Private control socket | A second channel opens in 31 ms with **no** second prompt. `ssh` appends 17 characters to `ControlPath`, so a path under `$TMPDIR` is too long (the limit is 104 bytes). The directory must be short, for example `/tmp/navette-<uid>/`. |
| Throughput, 1 GB read | 297 MB/s with 64 pipelined reads of 261120 bytes; `/usr/bin/sftp` takes 9 s for the same file (about 118 MB/s, including the write to disk). |

Not covered locally, left as manual tests: password and one-time-code prompts, FIDO keys, 1Password and Secretive agents, `ProxyJump`.

## S2. FTPS and TLS session reuse — partly passed, decision needed

Server: vsftpd 3.0.5 rebuilt with TLS in a temporary folder (Homebrew's vsftpd and proftpd are built without TLS), `require_ssl_reuse=YES`.

| Question | Result |
|---|---|
| Explicit TLS on Network.framework | Works. A framer below TLS reads the greeting, sends `AUTH TLS`, and on `234` calls `prependApplicationProtocol` with the TLS options. |
| Data channel with the public API only | **Fails**: `522 SSL connection failed: session reuse required`, with TLS 1.2 and 1.3, also when the same options object is shared. |
| Data channel with two non-public system functions (`sec_protocol_metadata_copy_serialized_session`, `sec_protocol_options_set_session_state`) | **Works with TLS 1.2** (three transfers in a row). Fails with TLS 1.3 against vsftpd. |
| Server that does not require reuse | Works with the public API, TLS 1.2 and 1.3. |
| `MLSD` | vsftpd does not implement it: the `LIST` fallback is mandatory. |

Options for servers that require session reuse (vsftpd default, FileZilla Server default):

1. Public API only. FTPS works with servers that do not require reuse; the others get a clear error explaining the server setting. No fragility.
2. Look the two functions up at run time and use them when present, capped at TLS 1.2 for FTPS, falling back to option 1 when they are missing. Works today; Apple can remove them in any release; not acceptable for the Mac App Store, which Navette does not target.
3. The deprecated Secure Transport API. Not tested; raises deprecation warnings, which the zero-warning rule forbids.

## S3. Keychain and ad hoc signing — confirmed

A password stored by one ad hoc build is readable by that build. A rebuilt binary with the same identifier but a different code hash is **not** allowed to read it silently: macOS waits for the user's approval. Consequence: after each update, macOS asks once per Keychain item.

Decision taken from it: Navette keeps all its credentials in a **single Keychain item**, so an update costs one approval, not one per bookmark.
