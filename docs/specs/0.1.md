# Navette 0.1 — specification

Status: **draft, awaiting validation**. Nothing is built until this document and [the plan](../plans/0.1.md) are approved, and the two spikes have reported.

## 1. Intent

Navette is a free, MIT-licensed, native macOS file transfer client: the protocol breadth of Cyberduck with the feel of Transmit. Version 0.1 proves the foundation on three protocols (SFTP, FTP/FTPS, WebDAV) with a single-pane browser, a reliable transfer engine and bookmarks.

What 0.1 must get right, because later versions build on it:

- **Speed and memory.** Listing a 10,000-entry folder stays fluid; a 50 GB transfer uses the same memory as a 50 MB one.
- **SSH that behaves like the user's terminal.** Whatever `ssh host` does in Terminal (config, agent, jump hosts, FIDO keys), Navette does too.
- **Safety.** Nothing destructive happens unseen; a cancelled or failed transfer never leaves a corrupt file.

### Scope of 0.1

| In | Out (version) |
|---|---|
| SFTP, FTP, FTPS (explicit TLS), WebDAV (http/https, Nextcloud and ownCloud presets) | S3 and compatibles (0.2) |
| Single-pane browser: list view, column view, path bar, filter, tabs | Dual pane Mac / server (0.2) |
| Transfers drawer, conflict policy, resume, rate limit | Sync with preview (0.2) |
| Bookmarks with folders and colors, recents, Keychain | Bookmark import and export (0.2) |
| Quick Connect (⌘K), connection sheet, Test button | Quick Open ⌘P (0.2, see Q2) |
| Quick Look, Open With and automatic re-upload | Bonjour servers (0.2, see Q1) |
| Drag and drop with Finder, both directions | Cloud drives, Finder mount, CLI (undecided) |
| Inspector, chmod | S3 metadata and pre-signed links in the inspector (0.2) |
| Demo mode, English and French | Azure, GCS, Swift, SMB, Cryptomator (0.3) |

## 2. Journeys

**J1. First connection to an SSH server.** The user presses ⌘K and pastes `sftp://deploy@staging.example.org:2222/var/www`. The sheet fills protocol, host, port, user and path. Under the fields, a "Resolved by ~/.ssh/config" block shows what `ssh -G` reports: real host name, user, port, identity files, jump host. Connect. The host is unknown: a sheet shows the key type and SHA256 fingerprint and asks to trust it. The key needs a passphrase: a second sheet asks for it, with "Remember in Keychain". The browser opens on `/var/www`. A "Save as bookmark" button sits in the tab.

**J2. Upload from Finder.** The user drags a folder from Finder onto the list. The transfers drawer opens: one row per top-level item, progress, speed, time left. A file already exists remotely: the conflict sheet shows both sizes and dates and offers Overwrite, Resume (when applicable), Rename, Skip, with "Apply to all". Each file is written under a temporary name and renamed at the end.

**J3. Download.** Drag files from the list to a Finder window or the Desktop, or press ⌘↓ to download to the default folder (Downloads, configurable). A local file that gets replaced after confirmation goes to the Trash.

**J4. Edit a remote file.** Right-click → Open With → an editor. Navette downloads the file to a private cache folder, opens it, and watches it. Each save uploads it back (temporary name, then rename); a discreet "Uploaded 14:02" status appears in the tab. If the remote copy changed since the download, Navette asks before overwriting.

**J5. Delete remotely.** Select items, ⌘⌫. Navette enumerates the selection (folders recursively, symlinks never followed), then shows a confirmation listing the items with a count and total size, stating that the deletion is permanent. It deletes exactly what was listed: anything that appeared in between is left alone and reported.

**J6. Interrupted transfer.** The network drops during a 4 GB upload. The row turns to "Interrupted", with Retry. Retry reconnects, checks the size of the partial temporary file and resumes from there. Cancel removes the partial file instead.

**J7. Changed host key.** `ssh` refuses the connection. Navette shows what happened, the new fingerprint as reported by `ssh`, the `known_hosts` line concerned, and the command to remove it. Navette does not edit `known_hosts` (Q4).

**J8. FTPS server with an untrusted certificate.** The connection stops; a sheet shows the certificate (subject, issuer, validity, SHA256) and the reason. The user can cancel, or trust this certificate for this bookmark. The decision is stored as the certificate fingerprint in the bookmark.

**J9. Demo.** `make demo` opens Navette with sample bookmarks and in-memory servers for each protocol, simulated latency and transfers, no network and no disk access.

## 3. Screens

Visual language: the Mopster redesign (native structure, gradient tints), with one tint per protocol instead of per module (SFTP, FTP/FTPS, WebDAV; S3 reserved).

1. **Main window.** Sidebar (Bookmarks as a tree with folders and color dots, Recents), tab bar (one tab per connection, tinted by protocol), toolbar (back, forward, up, view switcher list/columns, new folder, upload, download, inspector toggle, filter field), path bar, browser, transfers drawer at the bottom. Several windows are allowed.
2. **Browser, list view.** Sortable columns: name, size, modified, kind, permissions, owner. Multi-selection, inline rename, context menu (Open With, Quick Look, Download, Rename, Duplicate where the server can copy, Delete, Copy URL, Get Info). Hidden files toggle (⌘⇧.). Built on `NSTableView`: file promises to Finder and large folders both need it.
3. **Browser, column view.** Finder-style columns with a preview column for the selected file. Same selection, drag and context menu as the list.
4. **Empty state / welcome.** Shown in a tab with no connection: Quick Connect field, recent connections, "New bookmark".
5. **Connection sheet** (new bookmark, edit bookmark, Quick Connect expanded). Protocol picker with icons, fields adapted to the protocol, presets (Nextcloud, ownCloud fill the WebDAV path), SSH resolved-values block, "Test" button with an inline result, unencrypted warning for FTP and http.
6. **Trust and credential prompts.** SSH: unknown host key, password, key passphrase, one-time code, generic prompt (raw text from `ssh` when unrecognized). TLS: certificate sheet. All are sheets on the tab that triggered them and name the server.
7. **Transfers drawer.** Rows with direction, name, progress, speed, time left, state. Per row: pause, resume, retry, cancel, reveal. Global: pause all, clear finished, rate limit menu.
8. **Conflict sheet.** Described in J2.
9. **Destructive confirmation sheet.** Used for remote delete and for overwrites triggered by a move or rename. List of items, count, total size.
10. **Inspector** (⌘I, trailing sidebar). Name, kind, size, dates, owner and group, permissions as a 3×3 checkbox grid synced with an octal field, "Apply to enclosed items" for folders, symlink target, URL with a copy button. Fields the protocol cannot provide are hidden, not disabled.
11. **Settings.** General (download folder, default conflict policy, hidden files, double-click action), Transfers (simultaneous transfers per server, rate limit), Editing (default editor per type).
12. **Activity log** (window menu). Protocol commands and replies for troubleshooting, secrets redacted, in memory only.

Every screen has a `make screenshots` scene built from demo data, checked in light, dark and French.

## 4. Architecture decisions

### 4.1 Core model

- `RemotePath` stores the **raw bytes** the server sent, plus a display string. SFTP v3 and FTP have no guaranteed encoding, so this is the only way to honor "paths are data". Comparison and sorting use an NFC-normalized key; the bytes sent back are always the original ones.
- `RemoteItem`: path, kind (file, directory, symlink, other), size, dates, permissions, owner, group, link target.
- `RemoteFileSystem` (async, `Sendable`): `list` (streamed in batches), `stat`, `openRead(offset:)`, `openWrite(mode:)`, `makeDirectory`, `rename(overwrite:)`, `removeFile`, `removeDirectory`, `setPermissions`, `readLink`, `makeSymlink`, plus a `Capabilities` value (atomic rename, permissions, symlinks, upload resume, download resume, checksums, server-side copy). Views adapt to capabilities.
- Drivers: `SFTPFileSystem`, `FTPFileSystem`, `WebDAVFileSystem`, and `InMemoryFileSystem` for tests and demo, with injectable latency and faults (fail at byte N, disconnect, permission denied).
- `Session` owns the connections to one server: one for browsing, a small pool for transfers.

### 4.2 SFTP over the system OpenSSH

- Launch `/usr/bin/ssh` with an argument array: `-s`, `-T`, `-x`, `-a`, `-oClearAllForwardings=yes`, optional `-l`/`-p` only when the bookmark sets them, then `--`, the host, `sftp`. Host names are validated and always follow `--`, so a host can never be read as an option.
- Navette sets no option that would override the user's trust settings (`StrictHostKeyChecking`, `UserKnownHostsFile`, `IdentityFile`...).
- SFTP v3 client in the Core: packet codec, request ids, pipelined reads and writes sized from `limits@openssh.com`, and the OpenSSH extensions when advertised (`posix-rename@openssh.com` for atomic replace, `fsync@openssh.com`, `statvfs@openssh.com`).
- `ssh -G <host>` feeds the resolved-values block.
- **Askpass.** A tiny helper executable in the bundle is set as `SSH_ASKPASS` with `SSH_ASKPASS_REQUIRE=force`. It forwards the prompt text and `SSH_ASKPASS_PROMPT` to the app over a Unix socket in a private `0700` directory, authenticated by a per-connection token, and prints the answer. The helper holds no logic; the app classifies the prompt and shows the right sheet.
- Saved SSH passwords and passphrases are answered from the Keychain once per connection attempt; a repeated prompt always goes to the user. One-time codes are never stored.
- Several channels to the same host (browsing plus transfers) should authenticate once. Proposal: when the user's config sets no `ControlMaster`, Navette adds a private control socket with a short `ControlPersist` (Q10). The spike measures this.

### 4.3 FTP and FTPS

- Network.framework. Explicit TLS through a framer that performs `AUTH TLS` in clear and then inserts TLS (`prependApplicationProtocol`), `PBSZ 0`, `PROT P`, `EPSV` with `PASV` fallback, `OPTS UTF8 ON`, `MLSD` with `LIST` fallback (Unix and DOS parsers), `REST` for resume, `MDTM`/`SIZE`.
- **Main risk: TLS session reuse on the data channel**, required by vsftpd by default. Network.framework gives no explicit handle on the session to resume. Spike 2 decides. If it fails, the options to bring back to the author are a documented limitation or another TLS stack; nothing is added without approval.
- Plain FTP is supported with a visible "not encrypted" warning.

### 4.4 WebDAV

- `URLSession`: `PROPFIND` depth 1 parsed with `XMLParser`, `MKCOL`, `MOVE`, `COPY`, `DELETE`, ranged `GET`, streamed `PUT`. Basic and Digest authentication, TLS trust through the session delegate (J8).
- Uploads go to a temporary name then `MOVE`. No upload resume in 0.1 (Nextcloud chunked upload is a later addition).
- Plain `http://` needs an App Transport Security exception in `Info.plist` (Q8).

### 4.5 Transfers

- `TransferEngine`: queue, per-server concurrency (default 2), pause/resume/retry/cancel, token-bucket rate limit, conflict policy (ask, overwrite, resume, rename, skip), bounded buffers with backpressure.
- **Upload:** write to `.<name>.navette-part` next to the target, verify size (checksum when the protocol offers one cheaply), then rename over the target. Protocols without rename-over fall back to delete-then-rename, after the conflict policy has been applied.
- **Download:** write to `<name>.navette-part` in the destination folder, verify, then move into place. A replaced local file goes to the Trash.
- **Resume** only when the other side's size and date are unchanged since the partial was written; otherwise restart.
- **Cancel** removes the partial file on both sides. Navette's own partial files are removed directly; the Trash rule applies to the user's files.
- Recursive operations never follow symlinks. On download, a symlink that resolves inside the selection is recreated as a symlink; any other is skipped and listed in the summary (Q12).

### 4.6 App

- `AppEnvironment.live()` and `.demo()` as in Mopster. Services: bookmark store (JSON in Application Support, no secrets), credential store (Keychain; in-memory in demo), session factory, transfer engine, edit sessions, SSH config resolver.
- Open With: files live in `~/Library/Caches/io.github.romainrg.Navette/Edits/<session>/`, are watched at the folder level (editors save by rename), and are cleaned when the tab closes.
- Quick Look: downloads to the same cache; asks before fetching more than 50 MB.

## 5. Invariants

To be copied into `AGENTS.md` (increment 1), wording to be finalized there.

1. **Nothing destructive unseen.** Remote deletion (permanent), overwrite, and later sync deletions are confirmed with the list of items and their total. Deletion removes only what was listed.
2. **On the Mac, deleting means the Trash** (`FileManager.trashItem`), including local files replaced by a download. Exception: partial files Navette created itself.
3. **Explicit trust.** A changed SSH host key is never accepted silently; the SHA256 fingerprint is shown and `known_hosts` stays the user's. A TLS certificate error is never bypassed without showing the certificate.
4. **Secrets.** Credentials live only in the Keychain and never appear in a log, the activity window or an error message. A bookmark export contains no password unless encrypted with a passphrase.
5. **Network.** Navette contacts only the servers the user configured. No telemetry, no analytics, no update check in 0.1.
6. **Safe transfers.** Temporary name then rename where the protocol allows; size or checksum verified; resume never corrupts; a cancelled transfer leaves no partial file.
7. **Paths are data.** `Process` arguments are always an array, never a shell string; hosts and paths can never be read as options. Spaces, quotes, emoji and NFD pass through untouched; names are compared normalized and never rewritten. Recursive deletion and download never follow a symlink out of the selection.
8. **No third-party dependency, no new entitlement, no signing change** without the author's approval.
9. From the family: demo isolation (no network, no real disk), localization (English source, complete French), author hygiene, READMEs in sync, Core free of SwiftUI and AppKit.

## 6. Tests

- **Core unit tests:** SFTP codec (every packet type, truncated and oversized packets), `LIST` and `MLSD` parsers on fixtures, PROPFIND XML, URL parsing, `ssh -G` parsing, askpass prompt classification, name normalization, `TransferEngine` on `InMemoryFileSystem` (resume, every conflict policy, cancel at each stage, empty files, sparse files over 4 GB, hostile names, bounded memory), recursive enumeration with symlink loops.
- **Integration tests** (`make integration`, never in `make test` or CI), against servers started by the test script on high ports and stopped afterwards, with no system setting changed:
  - SFTP: `/usr/sbin/sshd` as the current user, temporary host key, temporary `authorized_keys`, a passphrase-protected key to exercise askpass.
  - WebDAV: `/usr/sbin/httpd` with `mod_dav` and a temporary configuration.
  - FTP/FTPS: needs a server macOS does not ship (Q7).
- **Manual tests** are listed for the author in each PR: prompts, drag and drop, Quick Look, Open With, real servers, FIDO keys, 1Password and Secretive agents.

## 7. Risks

| Risk | How it is handled |
|---|---|
| Askpass prompts are harder to classify than expected | Spike 1; a generic prompt sheet always exists as a fallback |
| FTPS data channel session reuse | Spike 2, before any FTP code |
| Keychain items and ad hoc signing: every new build has a different signature, so macOS may ask again for access to saved passwords after each update | Mini-spike 3 measures it; decision in Q6 |
| macOS Local Network permission: connecting to a LAN server shows a system prompt on first use, including for the `ssh` child process | Unavoidable; `NSLocalNetworkUsageDescription` explains it (Q8) |
| The helper executable adds nested code to sign in `build-release.sh` | Same ad hoc settings, no entitlement (Q11) |

## 8. Open questions

Each has a recommendation; a "yes to all recommendations" is a valid answer.

- **Q1. Bonjour servers in the sidebar:** 0.1 or 0.2? *Recommendation: 0.2.* It is not in the 0.1 list and adds `NSBonjourServices` declarations.
- **Q2. Quick Open (⌘P):** *Recommendation: 0.2*, same reason. "Go to path" (⌘⇧G) is in 0.1.
- **Q3. Column view:** *Recommendation: in 0.1, as the last feature increment*, so it can slip to 0.1.1 without blocking the release.
- **Q4. Changed host key:** should Navette offer a button that runs `ssh-keygen -R` after confirmation, or only show the command? *Recommendation: only show it in 0.1.*
- **Q5. New host key:** accepting it lets `ssh` append to the user's `known_hosts`, exactly as in Terminal. *Recommendation: yes.*
- **Q6. Keychain prompts after updates** (if the mini-spike confirms them): accept for 0.1 and document, or hold bookmarks' passwords back until there is a Developer ID? *Recommendation: accept and document.*
- **Q7. Development servers:** may I `brew install vsftpd` (needed for spike 2, it is the server that enforces session reuse) and `rclone` on this Mac? Neither is shipped. *Recommendation: yes to both.*
- **Q8. Info.plist additions:** `NSLocalNetworkUsageDescription`, and an App Transport Security exception so plain `http://` WebDAV works (with the unencrypted warning). *Recommendation: yes to both.*
- **Q9. Open With re-upload:** each save overwrites the remote file without a new confirmation, unless the remote copy changed. *Recommendation: yes*, opening for edit is the consent.
- **Q10. Private SSH control socket** when the user has none configured, so several channels authenticate once. *Recommendation: yes, if the spike shows it is reliable.*
- **Q11. Askpass helper:** a second ad hoc signed executable in the bundle, no entitlement. Confirm this is not a "signing change".
- **Q12. Symlinks on recursive download** as in 4.5. *Recommendation: yes.*
- **Q13. Spikes** live on `spike/*` branches that are never merged; their findings are committed as `docs/spikes/*.md`. *Recommendation: yes.*

Decisions I made that are not questions, to check while reading: `NSTableView` for the list; raw-byte paths; default of 2 simultaneous transfers per server; 50 MB Quick Look threshold; several windows allowed; implicit FTPS (port 990) included only if it comes for free after explicit TLS; FTP servers with legacy encodings are browsable byte-exact but get no encoding picker in 0.1.
