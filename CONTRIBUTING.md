# Contributing to Navette

Thank you for considering a contribution. Navette is maintained on a volunteer basis; clear reports and small, focused pull requests are the most helpful. By taking part you agree to the [Code of Conduct](CODE_OF_CONDUCT.md).

## Reporting a problem

- **Bugs**: open an issue with the bug template. Say which protocol and, if you can, which server software is involved. Never paste a password, a private key or an address you want to keep private.
- **Did Navette delete, overwrite or corrupt something it should not have?** Say so first: that is the most important kind of bug.
- **Security problems**: do not open a public issue; follow the [security policy](SECURITY.md).

## Setting up

You need macOS 14 or later, Xcode 16 or later and XcodeGen (`brew install xcodegen`).

```sh
git clone https://github.com/romainrg/Navette.git
cd Navette
make test    # builds, runs the unit tests and checks the French strings
make demo    # the app with sample servers: no network, no disk access
```

`project.yml` is the source of truth; `Navette.xcodeproj` is generated by `make generate` and is not committed. Run `make generate` after adding, removing or renaming a file.

### Integration tests

`make integration` tests the drivers against servers it starts itself as your user, on high ports, in a temporary folder: the system's `sshd` and Apache, and `vsftpd` from Homebrew when installed. It changes no system setting and is never part of `make test` or CI. FTPS tests need a TLS-enabled build of vsftpd, pointed to by `NAVETTE_IT_VSFTPD_TLS`.

Never run tests against a server you do not own, and never test deletion on real data.

## The rules that matter

These protect people's files. A pull request that weakens one of them will not be merged.

1. Nothing is deleted on a server or overwritten without the user having seen the list. Deletion removes exactly what was listed.
2. On the Mac, deleting means the Trash.
3. A changed SSH host key or an untrusted TLS certificate is never accepted silently, and FTPS never falls back to clear text.
4. Secrets live in the Keychain and in memory, nowhere else: not in logs, error messages, bookmark files or URLs.
5. Navette contacts only the servers the user configured.
6. Transfers go through a temporary name, are verified, and leave nothing behind when cancelled.
7. Paths and names are data: argument arrays for processes, raw bytes for names, no symlink followed out of a selection, no name rewritten.
8. No third-party dependency, no new entitlement, no change to the signing settings.

The full list, with where each rule is implemented, is in [AGENTS.md](AGENTS.md); the reasoning is in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Making a change

- Put logic in `NavetteCore` with unit tests; views, view models and macOS integration go in `Navette/`.
- A bug fix comes with a test that fails without it.
- A new protocol driver implements `RemoteFileSystem` and passes `DriverContract` against a real server in the integration tests.
- Every user-facing string goes in `Navette/Resources/Localizable.xcstrings` with its French translation. Xcode does not add keys for you: add them by hand in the form the compiler extracts, then run `make build && make check-strings`.
- For a UI change, render the screens with `scripts/screenshots.sh build/screenshots` (add `--language fr` for French), open the PNGs and check light, dark and French.
- The build has no warnings.
- Add a line under **Unreleased** in `CHANGELOG.md` for anything a user can notice, and update both READMEs when behavior changes: they keep the same sections in the same order.

Code and documentation are in English. Commit messages and pull request titles follow [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `docs:`, `test:`, `build:`, `ci:`, `chore:`).

## Pull requests

One topic per pull request. Fill in the template, including how you tested and, for UI changes, screenshots. If you used an AI assistant, say which and for what in the *AI assistance* section: you remain responsible for every line.
